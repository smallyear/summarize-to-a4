# 压缩规则（A/B/C 分级）

## 核心原则

**纸面压缩率 ≠ 信息损失率。** 40 页压成 2 页，留存文字可能只有 5%，但 A 类信息必须 100% 保留。

每删一段之前问一句：**"删了之后，某个结论会不会失去依据？"** 会 → A 类；不会 → B 或 C。

## 三档定义

### A 必留

删掉就改变判断的东西：

- 结论、判定结果、状态值
- 规则条文、阈值、时点、期限
- 关键数字、金额、比例、日期
- 判据与例外（"若……则……"、"除……外"）
- 定义（尤其是有专门定义、和日常理解不一致的词）
- 前置校验 / 兜底规则

### B 合并

信息有价值但不必逐个占行：

- 并列项 → 一行内用 ①②③ 串起来
- 举例说明 → 只留一句"例：……"
- 同类实例 → 一张表，每行一个实例
- 分散在多页的同一口径 → 合并成一节
- 重复出现的模板化表述 → "均按……处理"

### C 删除

- 过程性描述（"我们先检查了……然后……"）
- 截图、示意图、"如下图"引用
- 页眉页脚、页码、版本号
- 目录、致谢、免责声明
- 原文自己标了"待确认 / 草稿 / 拟调整"且**尚未定案**的内容——除非用户明确要
- 同义反复

## 留存率参考

| 原文规模 | 目标 | 典型留存文字比例 |
|---|---|---|
| ≤ 5 页 | 1 页 | 25–40% |
| 6–50 页 | 2 页 | 10–20% |
| 51–150 页 | 4 页 | 5–10% |
| > 150 页 | 6 页 | < 5% |

低于下界通常意味着砍多了（丢了 A 类），高于上界意味着还太啰嗦。

## 分格式策略

### PPTX

- **一页一个论点**：多数页的标题本身就是结论，可直接当小节标题用
- 大量示例页（连号、结构雷同）→ 合并成一句话或一行表
- 图表只取它想说的一句话，不要复述数据
- 备注页（notes）常含真正的解释，`extract.py` 会自动补成 `> 备注：…`，**读到时优先吸收，别当 C 类删掉**
- slidep 输出的 `**c1**（左上 48,29；右下 912,149）` 是坐标定位信息，属于 C 类，摘要里不要出现

### DOCX

- 保留原有标题层级，它通常已经是作者的逻辑线（`Heading N` 与中文「标题 N」都认得）
- 表格整表保留（表格压成散句会失去可比性）
- 各级"总则 / 附则 / 定义"最容易被忽略但最该保留
- 公文常见「一、（一）、1.」裸文本编号、不带标题样式，`extract.py` 抽不出来——这种要自己按编号断小节

### PDF

- 页眉页脚、页码、目录、水印 → C 类
- 脚注只在给出例外或定义时保留。注意：`extract.py` 抽出的脚注文字**混在正文流里、没有标记**，
  如果看到末尾以数字编号的短句（如「1. 数据来源于……审计报告」），那是脚注而不是正文结论
- **批注是 A 类**：`extract.py` 会把 PDF `/Annots` 抽成 `> 批注：…`，审阅意见经常是
  「此处数据待核」，必须吸收进摘要或至少在交付时提一句
- 扫描件抽不到字，先确认是否需要 OCR

### XLSX / CSV

- 只保留表头 + 关键行；行数多时按维度汇总成一行一组的表
- 数值列保留单位和量级，别只留裸数字
- 大矩阵（如财务三表）不压缩，整表保留
- 单表超过 200 行时 `extract.py` 只取前 200 行并 warning，尾部信息要靠用户补
- **表头是猜的**：首行全是短文字、且下面有数据 → 当表头；首行有空单元格或含纯数字 →
  当数据，整表保留并给空表头（warning 会说明）。猜错时不会丢行，最多表头是个空行
- 导出时注意：导出的表如果自带合并单元格/标题行，首行很容易被当成表头，看到
  warning 就别拿那份 `source.md` 当最终结构

### 网页 / HTML

- 抽正文后，导航、评论、推荐、广告都已剥掉
- **正文里的表格会按 GFM 整表保留**（含 `th`/`td`），可直接搬进摘要，别重新手打；原表没有 `<th>` 时会给一个等宽空表头，首行仍是数据，不会被吃掉当列名
- `li` / `blockquote` 内部的段落不会重复输出（旧版本会每段出现两次）
- `<title>` 与正文首个 `<h1>` 内容相同时只保留一份；无 `<title>` 时用首个 `<h1>` 当标题
- 标题层级映射：`h1` → `##`、`h2` → `###`、`h3`/`h4` → `####`（`###` 与 `####` 渲染同级，但层级不会再倒挂）
- 长文先看有没有 `h2/h3` 骨架，按骨架定小节
- "更新于""作者""阅读量"→ C 类

### 编码

- 源文件是 Windows 导出的 GBK 时，`extract.py` 会自动探测并转成 UTF-8，同时给 warning
- 判据分三级：UTF-8 能严格解通就当 UTF-8；解不通时看「UTF-8 容错解码的替换符占比」，
  占比低（< 25%）说明是 UTF-8 只坏了几个字节，保留原文只让个别字符变乱码；
  占比高才回退 GB18030
- 这样做的原因：gb18030 几乎能解任意字节序列，粗暴回退会把「坏了一个字节的 UTF-8」
  整篇解成乱码，还报「转换成功」
- 看到「个别字符会显示为乱码」时，正文是可信的，别把整份源文件当不可用而要求用户重传


## 速查型内容的成型套路

对照样本（35 页 PPT → 1 页 A4 双栏）之所以能压下来，靠的是对源结构做固定映射，而不是逐段缩写：

| 源里的页 | 落到纸上 |
|---|---|
| 规则原文页 | 顶部提示块：触发情形 + 一句话原文 |
| 「需提取内容 / 披露点」页 | 编号列表 ①②③，一行一点 |
| 判定页（C / ND / NA / E） | `[[C]]` 等标签 + 一行一条判级，整行着色 |
| 关键词页 | 单行灰底块，用 `·` 分隔 |
| 定位页（去哪个标题下找） | 小字一行，并入上一段 |
| **连号示例页**（十几页结构雷同） | 合并成一行：`示例 — C：3309/AR2023、8427/AR2024；ND：356/AR2023` |
| 思维导图 / 流程页 | 围栏代码块画 ASCII 决策树，每行 ≤ 30 字符 |
| part 之间的对应关系 | 交叉矩阵表（≤4 列、每格 ≤10 字） |
| 注意事项页 | `> !` 橙色警示块 |
| 纯截图页 | 删，只留一句「截图见原 PPT 第 N 页」 |

**示例页是最大的压缩来源**。35 页里 25 页是示例，全部收成两三行，纸面就出来了。

判级标签的四态语义（本 skill 内置）：

| 标签 | 含义 | 用途 |
|---|---|---|
| `[[C]]` | 符合 / 已披露 | 判定通过 |
| `[[ND]]` | 未披露 | 缺失 |
| `[[E]]` | 解释 / 例外 | 有解释但不达标 |
| `[[NA]]` | 不适用 | 本期无此情形 |

整行着色规则：表格一行里出现任一标签，整行染成对应底色。这样扫读时不用逐个读字，看颜色就能定位问题行。

## 写摘要时的硬约束

1. **一节一主题**，`##` 小节不超过 8 个——超过说明还没合并够
2. **表格优先于散文**：三列以内、每格不超过 30 字
3. **单元格不能换行**：需要多行就拆成两行表格；格内要写竖线就转义成 `\|`，否则会被切成两列
4. **每个 A 类数字都要有出处感**：至少让读者知道它属于哪条规则/哪个时点
5. **不写过渡句**："首先""其次""综上所述"全删，直接给内容
6. **不确定的不要编**：原文没写的结论，不要替它下
7. **不要把 `source.md` 的结构标记搬进来**：`## 第 N 页`、`### 内容`、坐标串都是定位用的，摘要里不该出现
8. **只用第一个 `#` 当大标题**：后续 `#` 会被 `render.py` 降成 `##`，但写成 `##` 更符合意图
9. **段落之间留空行**：`extract.py` 输出的 docx 正文是一行一段无空行，搬进 outline 时要么加空行、要么保持一行一段（`render.py` 会把顶格行各自成段），别指望换行被合并成一段
