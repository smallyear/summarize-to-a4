# 版面规格

## 纸张与页边距

- A4，`210 × 297 mm`（`595.28 × 841.89 pt`）
- 页边距 `10mm 11mm 10mm 11mm`——上窄下略宽，视觉上更稳
- 不做封面页、不做目录页。摘要就该一眼看到正文

## 字号档位（由 `render.py` 自动选择）

| 档 | 字号 | 行距 | 单元格内边距 | 适用 |
|---|---|---|---|---|
| 1 | 12.6pt | 1.82 | 6.2px | 内容很少，放大填满纸面 |
| 2 | 11.8pt | 1.76 | 5.8px | 内容偏少 |
| 3 | 11.1pt | 1.70 | 5.4px | 常规短文档 |
| 4 | 10.4pt | 1.65 | 4.8px | |
| 5 | 9.8pt | 1.60 | 4.2px | 内容轻松放下，最舒适 |
| 6 | 9.3pt | 1.55 | 3.8px | |
| 7 | 8.8pt | 1.50 | 3.4px | |
| 8 | 8.4pt | 1.45 | 3.0px | 密度偏高的专业文档常态 |
| 9 | 8.0pt | 1.40 | 2.6px | 仍能正常阅读的下限 |
| 10 | 7.7pt | 1.36 | 2.2px | 兜底，只在大表格压不下时用 |

选择逻辑：`--target-pages` 是**上限**，字号是手段。从档 1（12.6pt）往下逐档试，取**第一个**页数 ≤ `target_pages` 的档——等价于「不超过 N 页的前提下用尽可能大的字号」。短内容会停在 12.6pt 而不是缩在角落；内容太多则一路降到 7.7pt。

为什么要有 12.6pt 这一档：只有 11pt 封顶时，一页纸的文档常常只填到 1/3，看着像没写完。加高上限后短文档能自然撑满 A4，而长文档的分档行为完全不变（照样一路降到能塞下为止）。

全 10 档都塞不进 → 取页数最少的档 + `overflow:true`，此时必须回头砍内容而不是继续缩字。

档位序列是**降序**的，改档位时保持这个顺序，否则选档逻辑会取错（`regress.py` 会检查这一点）。

派生字号（全部相对正文字号缩放，改一处全局联动）：

- `h1` = 正文 × 1.66
- `h2` = 正文 × 1.13
- `h3` = 正文 × 1.04
- 提示块 / `th` / `code` / 枚举标签 = 正文 × 0.90
- 页脚 = 正文 × 0.84

## 分页铁律

这几条是踩坑换来的，改 CSS 时**不要动**：

1. `tr { break-inside: avoid }` —— 只约束行，不约束整表。给 `table` 加 `break-inside: avoid` 会让大表整块跳页，前面留一大片空白。
2. `thead { display: table-header-group }` —— 表格跨页时表头自动重复，否则第二页是一片没有列名的格子。
3. `h2, h3 { break-after: avoid }` —— 防止小节标题落在页底、正文跑到下一页。
4. 不在正文里插手动分页。让自动分页去断，只在明显不合理时用 `--target-pages N-1` 反向压缩。

## 视觉规范

- 主色 `#1f4e79`（标题栏左边线）、`#14293f`（标题文字）、`#1a2330`（正文）
- 表格边框 `0.5pt #d4dbe4`，表头底色 `#e9eef5`
- 小节标题：左 3px 主色竖条 + `#f2f5f9` 底
- 提示块：灰底 `#fafbfd` / 橙底 `#fff7f2`，左边 2px 色条，字号随正文缩放（× 0.90）
- 枚举标签：`C` 琥珀 `#fff3d1`、`NA` 蓝 `#e6f0fb`、`ND` 橙 `#fdeade`
- 字体栈：`PingFang SC → Hiragino Sans GB → Microsoft YaHei → Noto Sans CJK SC → sans-serif`
  （最终会转曲，字体只要能渲染出来即可）


## 分栏排版

### 几何（实测）

| 项 | 单栏 | 双栏 |
|---|---|---|
| 页边距 | `10mm 11mm 10mm 11mm` | `7mm 7mm 4mm 7mm` |
| 正文可用宽 | 532.9pt | 555.6pt（含栏间距） |
| 每栏宽 | — | **270.7pt**（`column-gap: 5mm`） |
| 每行中文字数 | 41–42（12.6pt） | 20.5（12.6pt）/ **30.8（8.4pt）** |

栏宽 270.7pt 与对照样本（一份高质量双栏速查）的 270pt 一致。

### CSS

```css
.cols { column-count: 2; column-gap: 5mm; column-fill: balance; }
```

**`column-fill: balance` 是受支持的**（weasyprint 70 实测：4 条 → 2/2，200 条 → 100/100，跨页时每页独立配平）。
不要因为「以为是 auto」而去手工切两半——真正需要手工处理的是「小节别被栏缝切开」，见下。

### 三种分栏模式

| 模式 | 开关 | 小节是否跨栏 | 版面密度 |
|---|---|---|---|
| 自然分栏 | `--columns 2` | **可能被切开** | 最紧 |
| 通栏标题 | `--span-headings` | 不会 | 小节多时会多花页 |
| 语义分栏 | `--pack-sections` | 不会 | 与自然分栏相当（推荐） |

实测（18 个「每节 2 条」的超短小节，目标 1 页）：

| 模式 | 页数 |
|---|---|
| 自然分栏 | 1 |
| 通栏标题 | 2（多花一页） |
| 语义分栏 | 1 |

语义分栏的代价：按实测高度装栏，若某小节比整栏还高，或装完页数不优于自然分栏，**自动退回自然分栏**（不牺牲页数）。

### 字号必须给「一行放得下」让位

双栏的全部意义是「一条占一行」。若 12.6pt 在 270pt 栏里只放得下 21 字，而条目有 30 字，条目就折成两行——**白从行末挪到了第二行，双栏白开**。

所以分栏时选档按 `(页数, 折行浪费行数, -字号)` 排序，并有 **8.4pt 可读下限**：
低于它只在一页内实在放不下时才用。

实测：100 条 24 字条目

| 配置 | 字号 | 页数 |
|---|---|---|
| 单栏 | 12.6pt | 4 |
| 双栏（不管折行） | 12.6pt | 3（每条折 2 行） |
| 双栏（让位给一行） | 8.8pt | **2** |

对照样本用 8.5pt，与本档位的 8.4pt 基本一致。

### 分栏下的硬约束（与单栏不同）

1. **表格 ≤ 4 列、每格 ≤ 10 字**。4 列 × 10–11 字总宽约 200pt，栏宽 270pt 尚有余量；每格到 12 字就撑爆。3 列可放宽到 15 字。格内长句一律改列表。
2. **等宽块每行 ≤ 30 字符**（含缩进）。`white-space: pre` 不折行，超宽会溢出到邻栏。
3. 小节标题的 `break-after: avoid` 保留；`tr { break-inside: avoid }` 也保留。
4. 页眉（大标题+副标题）与页脚留在栏外，保持全页宽。

### 语义色（对齐对照样本）

| 语义 | 用途 | 底色 | 边框 |
|---|---|---|---|
| `C` 符合 / 已披露 | `[[C]]` 标签、整行 | `#cfe8d4` | `#7bb389` |
| `ND` 未披露 | `[[ND]]` | `#f6d8d8` | `#d18a8a` |
| `E` 解释 / 例外 | `[[E]]` | `#fde9c8` | `#d9a45b` |
| `NA` 不适用 | `[[NA]]` | `#e2e5ea` | `#b9c4d6` |

表格里任一处出现判级标签，**整行**会被染成对应底色（速查表靠颜色扫读，不靠读字）。

小节标题：实心 `#1a3a6b` 底 + 白字；子标题：`#1a3a6b` 左竖条 + `#eef2f8` 底。
这两个值取自对照样本的实际取色。

### 等宽块（决策树）

围栏代码块会渲染成 `<pre>`（`SF Mono`，`white-space: pre`），用于判定流程：

```text
期内已评审?
├ 是 → C·当年，再判 reviewer 类型
└ 否 → 披露下次评审时间?
    ├ 是 → C·明年（part2/3 为 NA）
    └ 否 → 有解释不评审原因?
        ├ 是 → E
        └ 否 → ND
```

## 输出链路

```
Markdown ──render.py──> HTML ──weasyprint──> raw PDF ──gs -dNoOutputFonts──> 交付 PDF
```

`render.py` 用 `HTML(...).render().pages` 数页，不落盘，所以试几档也只有几秒。

## 选档与页数的关系

- `--target-pages` 是上限，不是配额。内容只有 2 页、target 写 6，结果就是 2 页，不会被拉长；`verify.py` 对此只给 `notes`，不是 `issues`。
- 想「少一页」就传 `N-1`；想「更紧凑」也是传 `N-1`，不要手工改 CSS。
- 短内容留白是**按上限选档**的副产品：字号取「塞得下的最大档」，末页自然可能稀疏。判断标准是 `verify.py` 的 `last_page_fill`，低于 25% 且页数 > 1 时，它会建议传 `--target-pages N-1` 再试一版——照做就能把末页那几行挤回上一页。
- `last_page_fill` 低于 25% 但页数已经是 1，说明内容确实少且字号已到上限，属正常。
## 调参对照

| 症状 | 原因 | 处理 |
|---|---|---|
| 某页大片空白 | 大表/大节整块跳页 | 检查是否给 `table` 加了 `break-inside:avoid` |
| 表头在第二页消失 | 缺 `thead` | 用 GFM 表格语法，`render.py` 会自动包 `thead` |
| 标题孤零零在页底 | 缺 `break-after: avoid` | 补规则，别手动分页 |
| 末页只有两三行 | 内容刚好溢出，或字号刚好卡上限 | `--target-pages N-1` 压到少一页，或砍 C 类 |
| 单页内容只占 1/3 | 内容本来就少，12.6pt 已是上限 | 正常现象，除非用户要求「填满一页」（此时加内容或表格，别改字号） |
| 列宽失衡、某列被撑爆 | 单元格里有长句/长 URL | 拆句、缩短，或改用列表 |
| 首列标签逐字换行（「迁」「移」各占一行） | 首列只放 2–4 个字的短标签，weasyprint 自动布局把它压到极限宽度 | 改成单列表格：`\| **标签** · 正文 \|`；要让短列稳住，就别让整列的最长单元格短于 7 个字 |
| 某个短列忽宽忽窄、数字列被挤成两行 | 同上，列宽随内容联动 | 若该列内容确实短，说明它不该独立成列，改成行内 `**加粗前缀**：正文` |
| 小节整体挤到下一页、上一页留白 | 标题 + 后续块被 `break-after:avoid` 绑定 | 合法现象；若留白过大，说明该节内容本就不属于这一页，考虑调换节序 |
| 打印出来是乱码 | 没转曲 | 必须走 `topdf.py`，检查 `gs --version` |
